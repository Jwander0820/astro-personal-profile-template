# 常見問題

這份問答給第一次使用 Astro、GitHub 或 Profile Studio 的人。內容設定的完整欄位請看 [`CUSTOMIZATION_GUIDE.md`](CUSTOMIZATION_GUIDE.md)；想讓 AI 訪談並整理自介，請看 [`AI_PROFILE_SETUP.md`](AI_PROFILE_SETUP.md)。

## Studio 與預覽

### 我 fork 之後，訪客還會看到線上 Studio 嗎？

預設不會。正式部署使用 `ONLINE_STUDIO_MODE=auto`，只允許 repository 或網站 allowlist 精確命中的目標。GitHub Actions 預設值只列出上游範本，因此別人的 fork 不會產生 `/studio/`、籤詩與 Icon 子頁，也不會顯示首頁 Links 卡片或頁尾入口。

如果想在自己的 fork 開放，請在 GitHub repository 的 **Settings → Secrets and variables → Actions → Variables** 設定：

```text
ONLINE_STUDIO_ALLOWED_REPOSITORIES=你的帳號/你的repository
```

自訂網域或 Cloudflare Pages 可改用 `ONLINE_STUDIO_ALLOWED_SITES=https://你的網址`。`ONLINE_STUDIO_MODE=public` 會直接公開，`off` 則一律關閉；這些只是建置開關，不是登入或密碼保護。

### 為什麼 Studio 預覽看不到「建立你的自介網站」？

這是刻意設計。那張卡片和頁尾的「線上 Studio」是範本導覽，不屬於你的自介資料，也不會寫入 `src/content/links/` 或設定包。正式網站只有在部署允許 Studio 時才會顯示；Studio 右側預覽會省略它們，讓你專注檢查自己的公開內容。

### 線上 Studio 會直接修改或發布 GitHub 嗎？

不會。線上版把文字草稿放在目前瀏覽器的 `localStorage`，上傳圖片放在 IndexedDB；除非你下載設定包，否則不會送到後端。它沒有 repository token，也不能 commit、push 或發布。

### 如何直接把內容儲存到專案？

Windows 可雙擊根目錄的 `start-studio.cmd`，或在 PowerShell 執行：

```powershell
npm.cmd run studio
```

開啟終端機列出的 `Profile Studio` 啟動連結。連結包含本次啟動的隨機憑證，頁面讀取後會從網址移除，並在同一分頁內保留到關閉。重啟服務後請使用新的啟動連結；直接開啟沒有憑證的網址仍可編輯瀏覽器草稿。本機背景服務成功連線後，「06 完成設定」會顯示「儲存到專案」；只有按下按鈕才會更新 `src/content/**` 與 `public/images/`。

若預設連接埠不可用，請開啟終端機最後列出的 `Profile Studio` 網址。

### 啟動時出現 `EACCES` 或 `EADDRINUSE` 怎麼辦？

`EACCES` 可能表示 Windows 保留了該連接埠；`EADDRINUSE` 表示已有服務使用它。`npm run studio` 會先嘗試預設的預覽埠 `4321` 與 API 埠 `4322`，不可用時優先使用固定備用埠 `14321`／`14322`；備用埠也不可用才由作業系統分配，並同步兩個編輯頁面的 API 位址。依終端機輸出的網址開啟即可，不需要刪除 Windows 保留範圍。瀏覽器草稿依網址保存；跨埠搬移草稿請使用匯出／匯入設定包。

也可在啟動前透過環境變數 `PORT` 與 `STUDIO_PORT` 指定偏好的預覽埠及 API 埠；不可用時同樣會自動改選。按 `Ctrl+C` 會停止預覽與 API。

### Links 卡片可以排序或取消第一張的主色嗎？

可以。在「02 公開連結」中使用每張 Links 卡片右側的上下按鈕調整順序，並在卡片內選擇「一般」、「主色強調」或「低調」。排序與樣式都會保存在設定包及專案 Markdown；第一張卡片不會再自動套用主色。

### Links 卡片可以上傳自己的 icon 嗎？

可以。在「02 公開連結」展開 Links 卡片，使用「自訂 icon（選填）」上傳 PNG、JPG、WebP 或 GIF（單張上限 5 MB），也可以貼上公開 HTTPS 圖片網址或 `/images/` 專案路徑。自訂圖片會優先於「Icon 名稱」顯示，等比例縮放到 24 × 24 px；按「移除自訂 icon」或清空圖片欄位後，就會恢復內建 icon。這個選項只用於 Links 卡片。

預覽、ZIP 設定包與本機「儲存到專案」都支援自訂 icon。單獨下載 JSON 只會保留圖片路徑或網址；要一起帶走上傳的圖片，請下載 ZIP。回答檔使用選填的 `links[].image`，內建圖示仍保留在 `links[].icon`。

### 為什麼是同一個 `/studio/`，卻有線上與本機兩種行為？

畫面是同一套。公開部署只有瀏覽器草稿與下載功能；`npm run studio` 另外啟動只監聽本機 loopback 的寫入服務（預設 `4322`，不可用時自動選埠），頁面偵測到它後才顯示專案寫入按鈕。

## 設定檔、圖片與功能

### 如何套用情境模板，又不丟掉已填的內容？

在「01 基本資料」選擇極簡名片、創作者、作品集或音樂生活。模板只調整配色、字型、排序與區塊顯示，保留個人文字、連結、圖片及播放清單；可用頂端「撤銷」復原。在「04 外觀」可重新勾選首頁內容。隱藏只影響版面，內容仍會保存在設定與專案中，不是私密保護。音樂生活不會自動代填歌單；非系統字型需要連線 Google Fonts。

### 如何展示或下載自己的名片？

只有 Studio「06 完成設定」→「名片與社群分享圖」提供名片製作，可選方形 1080×1080、直式 1080×1440 或橫式 1200×630，下載 PNG、複製正式網址；支援圖片分享的裝置也會顯示「分享圖片」。名片使用姓名、短介紹、自介、主色、字型與頭像，QR Code 指向正式首頁。正式首頁亮暗模式按鈕下方的「顯示網站 QR Code」只展示 QR Code 與網站連結，不提供名片產生或下載；Studio 內的首頁預覽也相同。

在 Studio「06 完成設定」填入公開 HTTPS「正式網站網址」（含 GitHub Pages 專案路徑），也可關閉首頁 QR Code 按鈕或分享圖的模板署名。未填網址時，正式 HTTPS 首頁使用目前頁面網址（不含查詢參數與錨點）；本機與 Studio 預覽不會把 localhost 或 Studio 網址做成 QR。產圖在瀏覽器完成，不會送往外部圖片服務。外部頭像需允許跨來源匯出；失敗時會提示並使用名字首字，改為上傳圖片即可重試。長文字會在圖片中省略，完整內容仍留在首頁。

### 不想向訪客展示網站 QR Code，可以關閉嗎？

可以。在 Studio「06 完成設定」→「名片與社群分享圖」，取消勾選「在公開首頁顯示 QR Code」，預覽中的 QR Code 入口就會隱藏。設定會隨 JSON、ZIP 或本機儲存保留，重新發布後正式網站才會套用。關閉後仍可在 Studio 製作與下載名片；首頁的自介、社群連結及已設定的社群封面不受影響。使用回答檔時設定 `sharing.enabled: false`。

### Studio 可以自動帶入正式網址嗎？

可以。開啟 Studio 時，既有草稿或專案中填過的網址會保留；空白時會帶入 Astro 的部署網址與 base 路徑（包含 `SITE_URL`／`GITHUB_REPOSITORY` 設定）。本機尚未設定公開部署網址時，會讀取目前專案的 GitHub `origin`：一般儲存庫預填 `https://使用者名稱.github.io/儲存庫名稱/`，`使用者名稱.github.io` 儲存庫使用根網址。沒有可辨識的部署設定或 GitHub origin 時仍須手動填寫。線上 Studio 只知道它所在專案的網址，無法得知訪客的 GitHub 帳號。

可直接改成自訂網域，或按「使用預設網址」改回推算值，也能撤銷。預填只更新瀏覽器草稿，不修改部署設定，也不代表網站已上線；仍需核對實際部署網址。若清空網址，下次開啟 Studio 時會再次套用預設值。

### 填入網址後，為什麼沒有看到 QR Code？

方形與直式名片的 QR Code 位於圖片下半部，需向下捲動查看；橫式位於右側。狀態顯示「名片已就緒」後可下載完整 PNG。網址不必先上線才能編成 QR Code；若仍顯示錯誤，確認使用公開 HTTPS 網址且沒有查詢參數或錨點。

### 社群封面如何套用到貼網址時的預覽？

在「06 完成設定」預覽分享圖後按「設為網站社群封面」，Studio 會產生橫式 PNG，保存成 `media.socialImage`。儲存到專案或下載 ZIP 後套用、建置與發布，正式頁的 `og:image` 才會使用這張圖；單獨 JSON 不含圖片檔。這是保存的快照，修改自介、配色或正式網址後請重新產生。可展開「目前的社群封面」查看、上傳自己的圖片或清空，清空後改回背景圖片。實際社群平台可能快取舊圖，Studio 預覽不是平台抓取成功的證明。

### 同時開啟兩個 Studio 分頁會互相覆蓋嗎？

主 Studio 與籤詩頁共用同一份專案草稿。另一個分頁更新後，舊分頁會顯示衝突提示並停止覆蓋瀏覽器草稿；畫面中的修改仍會保留。可以選擇「載入其他分頁草稿」，或明確選擇「保留此分頁並覆蓋」。有衝突時，本機儲存也會先停止。

不同專案的文字與圖片分開保存。本機依專案位置識別，公開版依網站網址與路徑識別；瀏覽器的網域與埠隔離仍然適用。舊版沒有專案識別的草稿會接續到第一個開啟的專案，原資料仍保留；其他專案請使用設定包搬移。草稿同步需要支援 Web Locks 的現代瀏覽器及 HTTPS 或 localhost；儲存不可用時，請下載設定包保存畫面中的內容。

### 刪錯卡片或匯入後，可以復原嗎？

主 Studio 頂部固定工具列的「撤銷／重做」保留此分頁最近 50 次修改，手機版以左右回轉箭頭顯示，捲動時仍可操作。支援卡片刪除、排序、圖片替換、JSON／ZIP 匯入及還原預設。連續輸入同一欄位會合併為一次修改。圖片也會一起復原；重新整理或關閉分頁後，撤銷記錄不會保留，長期備份請下載設定包。

撤銷只改變草稿與預覽，已寫入專案的檔案不會自動回復。需要把復原結果寫入專案時，請再按「06 完成設定」的「儲存到專案」。

### 替換或移除圖片後，下載包還會帶出舊圖片嗎？

ZIP 匯出與本機儲存只會包含目前頭像、封面、Links 自訂 icon、自介卡片及圖片板塊實際引用的上傳圖片。舊圖片可以留在瀏覽器供撤銷使用，不會一併匯出或阻擋本機儲存。同名且內容不同的上傳／匯入圖片會使用不同檔名，避免改掉另一個分頁或撤銷記錄中的圖片。

### 按下載或儲存時，如何找到需要修正的欄位？

驗證失敗時，Studio 會切到對應步驟、展開有問題的卡片並聚焦欄位，顯示持續可見的錯誤說明。無法對應單一欄位的設定檔或籤桶錯誤，則顯示整體提示。驗證規則與 CLI 及本機 writer 相同。

### 字型與 Markdown 能在 Studio 預覽嗎？

可以。內文與標題字型共用正式頁的設定；選擇外部字型後，預覽會載入相應的 Google Fonts，切回系統預設則不再請求外部字型樣式表。外部字型載入仍需要網路。

自介與卡片文字可預覽段落、粗體、斜體、清單、引用、連結、表格、註腳與程式碼區塊。註腳可跳轉及返回，標題的頁內連結錨點也會與正式頁一致。貼入的 HTML 會顯示為文字，不會執行。程式碼語法上色與 Astro 圖片最佳化仍以正式建置結果為準。

### ZIP 匯入失敗會影響原本的草稿嗎？

設定包會先驗證 JSON 與所有圖片的大小，再一次保存圖片。格式、大小驗證或圖片儲存失敗時，原草稿與已保存的圖片會保留；可修正設定包後重新匯入。

匯入上限為整包 50 MB、128 個 ZIP 項目、64 KB 檔名與附加資料、2 MB 回答文件、64 張圖片；每張圖片最多 5 MB，圖片總量最多 40 MB。下載設定包也會先檢查這些上限，超過時請縮小圖片後再下載。ZIP 只支援 Studio 產生的不壓縮格式，會檢查完整目錄、檔案校驗碼、路徑及重複檔名。只有新設定引用的圖片會新增到瀏覽器；既有圖片保留供撤銷與其他分頁使用。

### JSON 和 ZIP 設定包有什麼不同？

JSON 適合純文字設定，只保存圖片路徑或公開 HTTPS 網址。從裝置上傳的圖片檔不會塞進 JSON；需要完整備份或搬到另一台電腦時，請下載包含 `profile.answers.json` 與圖片的 ZIP 設定包。

### 圖片為什麼沒有顯示？

專案圖片應放在 `public/images/`，內容使用 `/images/檔名`。外部圖片必須是公開 `https://` 網址，而且對方網站需允許外連；需要登入、會過期或封鎖跨站載入的網址無法穩定顯示。Studio 上傳只接受通過檔頭檢查的 PNG、JPG、WebP 或 GIF，單檔上限 5 MB。

### YouTube 播放清單要貼 ID 還是完整網址？

兩者都可以。Studio 與 AI 回答檔會從 `youtube.com`、YouTube Music、`youtu.be` 等分享網址讀取 `list=`，並忽略 `si` 等分享參數。單支影片網址若沒有播放清單 ID，則不能當作唱盤清單。

### YouTube 分享連結會讓播放器取得 Studio 草稿嗎？

分享連結只用來讀取播放清單 ID，不會作為 JavaScript 執行。唱盤按下開始後才載入 YouTube 網域上的 iframe；本站不載入 `iframe_api` 外部腳本，播放器無法直接存取 Studio 編輯器與其瀏覽器草稿。暫停、隨機換曲與唱針進度由本站控制程式透過有限的訊息操作；播放器只收到公開播放清單與播放指令。

### 為什麼外部 Notion 或 YouTube 在預覽中不能操作？

正式元件仍受第三方服務的嵌入政策、Cookie、瀏覽器隱私設定與網路狀態影響。Studio 能確認本站的版面和設定，但無法繞過第三方禁止 iframe 或播放的限制。

### 要怎麼在 Studio 新增可嵌入的網頁？

到「05 其它功能」的「網頁內嵌」按「新增內嵌」，可以填公開 http(s) 網址，也可以直接貼 Notion 或 YouTube 的整段 `<iframe>`。Studio 只會取出安全的 `src` 與 `height`，不會執行或保存其餘 HTML；YouTube 一般影片、Shorts、直播與播放清單網址也會轉成正式 embed URL。直接 iframe 可設定 320～1200 px 高度；若右側預覽空白或被拒絕，代表來源網站不允許被嵌入，請改用預覽連結。

iframe 中真正必要的是 `src`；`title` 是無障礙說明，`height` 是顯示高度，`allowfullscreen` 與 `allow` 是授權全螢幕、播放或剪貼簿等能力。`width` 由本站響應式版面接管，`frameborder` 已由 CSS 取代。Notion 的 `v=` 等查詢參數可能代表指定檢視，Studio 會保留；YouTube 的 `si=` 是分享識別參數，不是播放必要值，轉換時會移除。

直接內嵌不可使用 `localhost`、`127.0.0.1`、IPv6 本機／私人位址、常見私人網段或含帳密的網址；這些網址可改成預覽連結，讓訪客自行選擇開啟。一般公開網站仍可直接內嵌。這項檢查不會查詢 DNS，也不能保證公開網域的重新導向不進入內網。

## AI 與發布

### 發布完成助手會自動上線嗎？

不會。「06 完成設定」可選 GitHub Pages 或 Cloudflare Pages，依步驟建立自己的儲存庫、保存設定、建置、檢查公開內容，再到對應平台部署。勾選進度只留在目前瀏覽器與專案範圍，不放進個人內容或匯出的 ZIP。填好上方正式網址後可按「開啟正式網站」親自確認；勾選代表你的手動確認，助手沒有連線驗證部署狀態。正式網址改變時，先前的網站確認會清除。網頁版 Studio 不持有 GitHub 或 Cloudflare 憑證。

### 哪些資料一定要提供給 AI？

只有顯示名稱必填。短標題、關鍵字、自我介紹、地點、社群、email、精選連結、播放清單與互動功能都能跳過。AI 不應自行杜撰經歷、雇主、網址或聯絡方式。

### 一般聊天型 AI 產生 JSON 後要放哪裡？

到 Profile Studio 的「06 完成設定」，把 JSON 貼進 AI JSON 區域並按「驗證並載入草稿」。先用右側正式預覽檢查，再下載 ZIP／JSON；本機模式仍要另外按「儲存到專案」。

### AI 說已經發布網站，代表真的完成了嗎？

不一定。不能存取 repository、終端機與 GitHub Actions 的一般 AI 只能訪談及產生文字或 JSON。具備工具的 coding agent 也必須先完成 build、列出將公開的內容與 Git diff，得到你的確認後才能 commit／push，最後還要核對部署結果。

### 發布前最重要的檢查是什麼？

確認姓名、地點、email、雇主與每個網址都願意公開；確認 `origin` 是自己的 repository，不是上游範本；不要提交 `profile.answers.json`、token、API key 或密碼。第一次使用 GitHub Pages，還要在 **Settings → Pages** 選擇 **GitHub Actions**，並視 GitHub 提示啟用 fork 的 workflow。

## 問題排除

### 為什麼上游 Actions 的品質檢查有警告，網站仍然部署成功？

這是預期行為。部署的硬性條件只有依賴安裝、Astro 診斷、內容驗證、靜態建置、artifact 上傳與 Pages 發布。Studio matrix、Playwright、UI contracts、Profile tools、模板安全與預設內容是上游範本的維護訊號，失敗時應修正，但不再阻擋一份可正常建置的網站上線；一般 fork 不執行這組範本專用品質鏈。

### 儲存後 Git 顯示很多不相關變更怎麼辦？

先不要 commit。檢查 `git status` 與 diff，只保留這次要公開的內容和圖片。本專案會跳過內容完全相同的寫入，以避免無意義的 mtime 變更；若仍出現大量變更，請確認是否匯入了不同的設定包或重設了既有內容。

### Windows build 出現 `EPERM` 是程式壞掉嗎？

不一定。Astro／Vite 的快取檔可能正被另一個開發伺服器或 IDE 鎖住。先停止仍在執行的 dev／Studio 行程，再重跑 `npm.cmd run build`。不要因為單一快取鎖定就刪除內容或認定部署程式有問題。

### 還是不知道該從哪裡開始？

只想編輯內容：執行 `npm.cmd run studio`。想讓 AI 協助：把 [`AI_PROFILE_SETUP.md`](AI_PROFILE_SETUP.md) 的提示詞交給具備檔案與終端機權限的 coding agent。只用手機或一般聊天 AI：先產生 JSON，再到允許公開的線上 Studio 匯入並下載設定包。

## 套用答案檔與本機儲存

### 為什麼先執行 profile:plan？

`profile:plan` 會驗證答案與列出預計新增、更新的內容及圖片，但不會寫入專案。這能在公開個人資訊或清空集合前先檢查影響。

### replace 與 merge 有什麼差別？

`replace` 是預設完整狀態：省略的可選欄位會依契約預設重設，不會保留既有值。`merge` 只更新回答檔明確提供的頂層欄位，未提供的社群、連結、區塊與外觀保持原狀。

### 本機 Studio 儲存失敗會留下部分圖片嗎？

正常情況不會。Studio 先驗證設定與圖片，再在暫存副本計算變更；使用者確認計畫後才提交。若提交途中失敗，writer 會回復已寫入檔案。同名但內容不同的圖片會改用 digest 後綴，不會覆蓋原檔。
